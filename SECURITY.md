# SECURITY POLICY — SECURE HEALTH PAYMENTS GATEWAY

## 1. Security Architecture Principles

Secure Health Payments Gateway is engineered with **Defense-in-Depth** and **Zero-Trust** architectural standards:

1. **Least Privilege & Role-Based Access Control (RBAC):** Three strictly isolated access tiers:
   - `PATIENT`: Limited to personal receipts and consent settings. Zero access to clinic ledgers or other patients' identifiers.
   - `PROVIDER`: Enforced tenant boundaries. `org-afyacare` can never query, inspect, or resolve records belonging to `org-mediplus`.
   - `SECURITY_ADMIN`: System-wide telemetry, threat indicators, and rate-limiting policies without access to clinical medical charts.

2. **Server-Side Authorization & Anti-IDOR:**
   Every API endpoint resolving resources (`/api/payments/:id`, `/api/security/events/:id/resolve`) re-evaluates the authenticated user's `role` and `organizationId` directly in the database query layer. Frontend claims are never trusted blindly.

3. **Data Minimization (Kenya Data Protection Act 2019 / GDPR):**
   - **Zero Raw PAN/PIN:** Neither credit card PANs, CVVs, nor M-Pesa personal identification numbers are ever transmitted to or stored in backend persistence.
   - **Pseudonymized Patient Reference:** Identifiers are tokenized into format `PAT-****-****`.
   - **Masked Phone Numbers:** MSISDN values are masked as `+254 7** ***678`.

4. **Cryptographic Tamper-Evident Audit Logging (IBM Guardium Pattern):**
   Every audit entry contains:
   - `previousHash`: The SHA-256 hash of the immediately preceding audit record.
   - `entryHash`: `SHA256(id + timestamp + previousHash + actorId + eventType + payload)`
   Any unauthorized modification, insertion, or deletion breaks the hash chain, immediately alerting the SOC during chain verification.

5. **Frontline API Threat Protection (IBM DataPower / API Connect):**
   - Token-bucket rate limiting (60 requests/minute per client IP).
   - SQL Injection (SQLi) pattern detection and rejection.
   - Cross-Site Scripting (XSS) payload inspection.
   - Strict Content Security Policy and CORS restrictions.

6. **IBM watsonx.ai Credential & Data Isolation:**
   - **Zero Client Credential Exposure:** IBM Cloud API Keys (`IBM_CLOUD_API_KEY`) are stored purely in server-side environment variables or secrets. No API keys or IAM tokens are ever transmitted to the frontend, embedded in HTML, or logged.
   - **Server-Side Token Lifecycle:** IAM bearer tokens are fetched server-side from `https://iam.cloud.ibm.com/identity/token`, held only in server memory, and cached with a 5-minute safety buffer prior to expiration.
   - **Zero-PII AI Telemetry:** Telemetry payloads submitted to `https://eu-de.ml.cloud.ibm.com/ml/v1/text/generation` are filtered strictly through the Guardium sanitization pipeline. Patient names, national IDs, and financial payment accounts are stripped.
   - **Deterministic Security Rule Supremacy:** The hybrid risk engine enforces strict rule precedence: AI cannot downgrade high-risk flags generated by deterministic security rules. If the AI model service is unavailable or times out, payments continue safely using deterministic fraud rules.

## 2. Threat Model (STRIDE Assessment)

| Threat Category | Potential Attack Vector | Gateway Countermeasure |
|---|---|---|
| **Spoofing** | Forged client identity or credential stuffing | Signed HMAC-SHA256 JWT tokens with 8-hour expiry; bcrypt password hashing with salt rounds. |
| **Tampering** | Altering payment amounts or audit history | Chained SHA-256 Guardium ledgers; signed token payload validation; server-authoritative service pricing. |
| **Repudiation** | Denying a suspicious or unauthorized transaction | Cryptographic audit logs linking actor ID, timestamp, and client hardware fingerprint. |
| **Information Disclosure** | IDOR attack accessing another clinic's transactions | Server-enforced tenant filtering on every endpoint. PII masking on all returned payloads. |
| **Denial of Service** | Flooding payment submission endpoints | DataPower token-bucket rate limiter (HTTP 429 after 60 req/min). |
| **Elevation of Privilege** | Normal patient invoking SOC configuration | Hard-gated Express role middleware (`requireRoles('SECURITY_ADMIN')`). |

## 3. Incident Response & Vulnerability Reporting

If you identify a security vulnerability in this gateway:
1. Do not open public issues disclosing exploit details.
2. Contact the security team at `security@healthpay-gateway.demo`.
3. Provide replication steps, HTTP request logs, and affected component IDs.
